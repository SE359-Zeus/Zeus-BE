# Installing the Sales Service

The **Sales** service manages clients, sales orders, and fulfillment workflows.

- **Port:** 8082
- **Database:** SQLite
- **Image:** `ghcr.io/se359-zeus/zeus-be/sales:latest`
- **Depends on:** SCM, MRP (pings both at startup), System (JWT auth)

---

## Prerequisites

### Bare Metal
- **Go 1.26+**
- **No CGO required** -- Sales uses `glebarez/sqlite`, a pure-Go SQLite driver
- **Valkey** or **Redis** (optional)
- **RabbitMQ** (optional)

### Docker
- **Docker 24+** with Compose V2

---

## Configuration

Sales reads a `.env` file in its working directory or environment variables directly.

```env
# ── Required ────────────────────────────────────────────────────────────────
PORT=8082
BASE_URL=http://localhost:8082
SQLITE_DB=./sales.db
JWT_PUBLIC_KEY_PATH=jwt_public.pem

# ── Required: cross-service URLs ────────────────────────────────────────────
SCM_URL=http://localhost:8081
MRP_URL=http://localhost:8083

# ── Optional: API keys for service-to-service calls ─────────────────────────
SCM_API_KEY=scmkey01-admin-20260524
MRP_API_KEY=mrpkey01-admin-20260524

# ── Optional: cache ─────────────────────────────────────────────────────────
VALKEY_ADDR=localhost:6379

# ── Optional: message broker ────────────────────────────────────────────────
RABBITMQ_URL=

# ── Optional: logging ───────────────────────────────────────────────────────
LOG_LEVEL=info

# ── Optional: observability ─────────────────────────────────────────────────
APP_ENV=development
ALLOY_URL=
ALLOY_USERNAME=
ALLOY_PASSWORD=
```

### Environment Variable Reference

| Variable              | Code Default                       | Description                              |
|-----------------------|------------------------------------|------------------------------------------|
| `PORT`                | `8082`                             | HTTP listen port                         |
| `BASE_URL`            | `http://localhost:8082`            | Service base URL                         |
| `SQLITE_DB`           | `./sales.db`                       | SQLite database file path                |
| `RABBITMQ_URL`        | (empty)                            | RabbitMQ connection URL                  |
| `VALKEY_ADDR`         | `localhost:6379`                   | Valkey/Redis address                     |
| `JWT_PUBLIC_KEY_PATH` | (empty)                            | Path to RSA public key PEM               |
| `MRP_URL`             | `http://localhost:8083`            | MRP service URL                          |
| `SCM_URL`             | `http://localhost:8083`            | SCM service URL                          |
| `SCM_API_KEY`         | (hardcoded default)               | API key for SCM service calls            |
| `MRP_API_KEY`         | (hardcoded default)               | API key for MRP service calls            |
| `LOG_LEVEL`           | `info`                             | Log level                                |
| `APP_ENV`             | `development`                      | `development` / `staging` / `production` |
| `ALLOY_URL`           | (empty)                            | Alloy Loki-receiver for log push         |
| `ALLOY_USERNAME`      | (empty)                            | Grafana Cloud user ID                    |
| `ALLOY_PASSWORD`      | (empty)                            | Grafana Cloud API token                  |

> **Note:** Sales accepts multiple env var names for some settings (e.g. `PORT` or `SALES_PORT`,
> `SQLITE_DB` or `SALES_SQLITE_DB`). The first matching variable wins.

### JWT

Sales verifies incoming JWTs with an RSA public key. Copy the public key generated by the **System** service to `sales/jwt_public.pem`.

## Option 1: Bare Metal

```bash
cd sales/

# 1. Install Go dependencies
go mod download

# 2. Run migrations (destructive -- deletes existing DB!)
make migrate

# 3. Seed the database
#    Requires scm-manifest.json from the SCM seeder.
#    The file ships at sales/scm-manifest.json for convenience.
make seed

# 4. Start the server
make run
#    Listening on http://localhost:8082
#    Swagger UI: http://localhost:8082/docs/
```

### Available Make Targets

| Command        | Description                                              |
|----------------|----------------------------------------------------------|
| `make run`     | Start the Sales server                                   |
| `make migrate` | Run migrations (deletes existing DB artifacts first!)    |
| `make seed`    | Seed the database from scm-manifest.json                 |
| `make test`    | Run all tests                                            |

### Seeding

The Sales seeder reads `sales/scm-manifest.json` (generated by the SCM seeder). A copy is already committed to the repo for convenience. To regenerate:

1. Run the SCM seeder (see [INSTALL_SCM.md](INSTALL_SCM.md))
2. Copy the output `scm-manifest.json` to `sales/scm-manifest.json`
3. Run `make seed`

## Option 2: Docker

### Build

Build from the **repo root**:

```bash
docker build -f sales/Dockerfile -t zeus-sales:latest .
```

> **Note:** Sales uses `CGO_ENABLED=0` (pure-Go SQLite driver), so no C toolchain is needed in the build.

### Run

```bash
# 1. Start Valkey (optional)
docker run -d --name zeus-sales-valkey \
  -p 6382:6379 \
  valkey/valkey:latest

# 2. Run migrations + seed
docker run --rm \
  -v zeus-sales-data:/app/data \
  zeus-sales:latest \
  ./migrate -db /app/data/sales.db

docker run --rm \
  -v zeus-sales-data:/app/data \
  zeus-sales:latest \
  ./seeder -db /app/data/sales.db

# 3. Start the server
docker run -d --name zeus-sales \
  -p 8082:8082 \
  -v zeus-sales-data:/app/data \
  -e PORT=8082 \
  -e SQLITE_DB=/app/data/sales.db \
  -e JWT_PUBLIC_KEY_PATH=jwt_public.pem \
  -e VALKEY_ADDR=redis://zeus-sales-valkey:6379 \
  -e SCM_URL=http://host.docker.internal:8081 \
  -e MRP_URL=http://host.docker.internal:8083 \
  -e APP_ENV=development \
  --link zeus-sales-valkey \
  zeus-sales:latest
```

### Docker Compose (production-style)

The included `sales/docker-compose.yml` defines a full production stack with Tailscale networking, Valkey, migration, seeder, and the server. See that file for details.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `scm connection failed` at startup | SCM not running | Start SCM first; check `SCM_URL` |
| `mrp connection failed` at startup | MRP not running | Start MRP first; check `MRP_URL` |
| `failed to open sqlite database` | Missing write permission | Ensure DB directory is writable |
| `valkey connection failed` | Valkey not running | Non-fatal; runs without caching |
| `rabbitmq` warning | RabbitMQ not running | Non-fatal; runs without messaging |
| Seeder fails with manifest error | Missing `scm-manifest.json` | Copy from SCM seeder output |
